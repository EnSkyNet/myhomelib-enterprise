## Executor cancellation completion — 2026-09-23
- Підтверджено: `SpringExecutorAdapter.submitCancellable(...)` скасовував лише backing `Future<?>`. Якщо задача була скасована до старту, worker вже ніколи не виконувався, а окремий `CompletableFuture<T>` залишався незавершеним назавжди.
- Виправлено: cancel action тепер скасовує і backing worker, і completion future; race із уже завершеним worker безпечний через idempotent `CompletableFuture.cancel/complete`.
- Тести/збірку НЕ запускали.

## Metadata provider timeout worker leak — 2026-09-23
- Підтверджено: `MetadataLookupService` застосовував `CompletableFuture.orTimeout(...)` до звичайного `executor.submit(...)`. Timeout завершував лише future, але backing provider task продовжував працювати у shared executor; завислий/повільний provider міг поступово виснажити worker pool.
- Виправлено: metadata provider calls переведено на `ExecutorPort.submitCancellable(...)`; при `TimeoutException` backing task явно скасовується. Глобальний cancel flag не встановлюється, щоб timeout одного provider-а не скасовував інші незалежні metadata providers.

## Organizer EPUB fingerprint: physical/semantic TOCTOU

## Duplicate Review: stale source-book context within same collection

## 2026-09-23 — Organizer whole-item stability + stale fingerprint cache

- `AnalyzeLibraryOrganizationUseCase` previously opened the same source independently for signature detection, metadata extraction and fingerprinting without a guard spanning the whole sequence. A pathname replacement between stages could create one plan item from mixed physical versions (for example, old format detection + new metadata/hash).
- Added whole-item source identity checks (size, mtime and fileKey where supported) immediately after format detection and again after the complete item analysis. A changed source now fails closed instead of producing a mixed plan.
- `BookFingerprintService` had a stat-keyed cache `(path,size,mtime,fileKey,format)`. Those attributes can remain unchanged after an in-place rewrite, so duplicate analysis could reuse a stale SHA-256/semantic fingerprint. Removed the cache: each analysis now derives fingerprints from the current bytes. Apply already re-verifies destructive sources, but Analyze itself must also be correct.
