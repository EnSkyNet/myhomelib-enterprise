# MyHomeLib 8.0.0 — ітерація 61: наскрізний аудит користувацьких сценаріїв

Дата: 2026-10-09. База: ітерація 60. Робота виконана в декілька циклів аналізу, виправлень і регресійних тестів.

## Зміни

1. Автоматичний імпорт із папки: під час сканування не формується повний список шляхів у пам'яті; налаштування папки повторно використовуються протягом одного сканування; асинхронні перевірки файлів використовують легкий запит до БД замість дорогого підрахунку всіх станів. Скасовані таймери вилучаються із черги ScheduledThreadPoolExecutor.
2. Черга автоматичного імпорту: виправлено втрату wake-up події при завершенні попереднього drain; при відхиленні запуску ExecutorPort стан `draining` не залишається заблокованим.
3. Публікація конвертованої книги: результат спершу повністю записується в приватному тимчасовому каталозі кінцевої файлової системи, після перевірки вмісту переноситься під кінцеву назву без дозволу заміни існуючої книги. Не залишає частково скопійованої книги під кінцевою назвою при збої запису.

## Залишкові ризики і напрямки продовження

- Виміряти на Windows: органайзер із `MOVE` / `CONVERT` / `OPTIMIZE` та реальною SQLite; облік часу диска, мережевих шляхів та дефіциту місця.
- Провести реальні UI сценарії з великими колекціями, швидкими кліками, скасуванням та перемиканням між колекціями.
- Протестувати відмови живих зовнішніх сервісів, реальні пристрої/USB/оновлення та сценарії відновлення після аварійного вимкнення живлення.
- Провести додатковий аудит SQL-транзакцій і блокувань, особливо масових змін каталогу та довгих індексацій.
- Без конкретних вимірювань не робити висновків про відсоток прискорення на користувацькій бібліотеці.

Висновок: пройдені тести не доводять відсутності всіх можливих дефектів. Файли користувацьких книг не змінювалися; для приймального тестування використовувати копію бібліотеки.
