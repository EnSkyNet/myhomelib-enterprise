# MyHomeLib: спрощення V33 → V34 і релізні пріоритети

## Мета

Спростити підтримку настільного застосунку без збільшення кількості модулів і без зміни правил безпечного переміщення книг. Не додавати захистів заради гіпотетичних сценаріїв; спершу підтверджувати проблеми.

## Перевірене архітектурне рішення

- `LibraryOrganizerUiService` більше не містить реалізації трьох операцій із папками авторів і окремого діалогу вибору для офлайнового експорту.
- `OrganizerAuthorFolderActions` у тому самому `myhomelib-ui` володіє лише переглядом назв, read-only аудитом, CSV-звітом та експортом вибраних назв. Він не змінює бібліотеку, не виконує Apply/Undo, не отримує нових Spring-залежностей та не створює нового Maven-модуля.
- Кнопки й структура майстра залишилися тими самими. Перевірки активної колекції, вибір зовнішнього шляху, фонові операції та атомарний запис експортних файлів збережено.
- Додаткові UI-тести перевіряють відмову при некоректному шляху SQLite і заборону експорту всередину бібліотеки.

## Що не потрібно міняти без доказів

Не вилучати SHA-256, SQLite/Flyway, журнал Undo, перевірку застарілих записів Reader та відмову від перезапису файлів. Не переписувати весь застосунок із нуля і не дробити 21 Maven-проєкт механічно: це потребує аналізу залежностей, вимірів тривалості збірки і міграційного плану.

## Реальні критерії релізу (Windows)

1. Інсталятор/portable: встановлення, запуск без засобів розробника, видалення без втрати бібліотеки.
2. Типовий цикл: відкрити колекцію, імпортувати INPX, пошукати книгу, відкрити FB2/EPUB, зберегти позицію, закрити й відновити.
3. Організатор: preview → apply → cancel → retry → undo на **копії** бібліотеки; відсутність втрат і несподіваних перезаписів.
4. Заміряти холодний/теплий запуск, idle/пікову RAM, час пошуку та організації 100/1000 книг, кількість помилок за тривалу сесію. Не вигадувати порогів до затвердження тестової машини.
5. Перевірити кириличні/довгі шляхи, NTFS/UNC, Windows DPAPI, поведінку за втручання антивіруса.
6. Зафіксувати список неуспішних або пропущених тестів і провести ручну перевірку критичних функцій перед позначенням production-ready.

## Межі цього циклу

V34 не доводить прискорення UI, зниження RAM або завершеного Windows-приймання. Перенесення UI-методів — зміна підтримуваності, а не переписування бізнес-логіки. Не використовувати реальну `Flib.db` чи книги для тестів без окремого дозволу.
