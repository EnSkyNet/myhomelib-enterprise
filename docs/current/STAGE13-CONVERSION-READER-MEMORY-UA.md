# MyHomeLib R18 — Stage 13: конвертація, перевірка форматів і пам'ять Reader

Базова версія: Stage 12 (2026-10-16). Зміни не виконують будь-яких операцій над реальною бібліотекою користувача.

## Виявлені дефекти

1. `BookConversionUiService.runConversions()` заздалегідь виділяв майбутні задачі та callback-ланцюжки для **кожної** вибраної книги при реальній паралельності дві конвертації; на завершенні утримував результати всіх книг і підраховував їх у потоці JavaFX. Це створювало зайві O(N) об'єкти.
2. Перевірка доступних форматів (`commonFormats`) виконувалася безпосередньо з обробника натискання JavaFX. Для великої вибірки могла затримувати інтерфейс ще до появи діалогу.
3. У `NewReaderPersistenceService` кеш `lastSavedPositions` зростав без межі впродовж сесії читання, попри те що його вміст уже було записано в SQLite.
4. Нові мовні ключі мають підтримуватися і в `Lang/`, і в ресурсах UI.

## Внесені зміни

- Використано `AsyncBatchLaneRunner` з двома активними конвертаціями без N об'єктів `CompletableFuture` і N результатів. Помилки кожної книги зберігаються у технічному журналі; у вікні — локалізований агрегований підсумок. Облік успішних/помилкових/скасованих задач і прогрес потокобезпечний; публікації прогресу обмежені за частотою та не можуть зменшувати виконаний лічильник.
- Перевірка форматів виконується фоновим `UiBackgroundExecutor` з координованим `LibraryOperationType.QUERY`; UI відображає результат після завершення. Поки йде одна перевірка, повторна не запускається.
- `lastSavedPositions` переведено на синхронізований LRU з лімітом 512. Витіснення вже збереженої позиції не видаляє її з SQLite, тому повторне завантаження залишається можливим.
- Синхронізовано повідомлення трьома мовами в обох копіях каталогів.

## Перевірки і обмеження

- Тести охоплюють обмеження паралельності, скасування, часткові помилки, оновлення прогресу, фонову перевірку форматів. Тест Reader зберігає 750 різних книг, перевіряє ліміт 512 і відновлення витісненої позиції з репозиторію.
- Повний Maven clean verify та статичні перевірки релізу виконуються окремо, їх результати й логи додаються до доказового архіву.
- Місце для вихідного списку ID залишається O(N). Пам'ять сторонніх конвертерів/Calibre, буферів ZIP/EPUB і JavaFX тут окремо не виміряна.
- У `PositionAutosaveCoordinator` залишаються карти ревізій і блокувань, де необхідно зберігати причинний порядок конкурентних записів. Механічне очищення без додаткових тестів ризикує перезаписом новішої позиції; у цьому етапі їх не змінювали.
- Windows, локальний диск D: та реальна `Flib.db` недоступні для перевірки; жодне масове перейменування не виконувалося.
