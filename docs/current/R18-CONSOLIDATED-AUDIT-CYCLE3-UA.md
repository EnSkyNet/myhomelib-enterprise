# MyHomeLib Enterprise 8.0.0 R18 — консолідований аудит: цикл V3

**Дата:** 16 жовтня 2026 року.
**Початкова версія цього циклу:** `MyHomeLib-Enterprise-8.0.0-R18-CONSOLIDATED-AUDIT-2026-10-16-SOURCE-V2.zip`.

**Статус V3:** виправлена та частково перевірена вихідна версія. **Повної Maven/Windows-приймальної перевірки немає; production sign-off не надано.**

## 1. Що саме перевірено

Використано **саме повний ZIP V2**, а не давніші каталоги робочого сеансу. Його вміст розпаковано у чистий каталог і використано для точкового продовження аудиту операцій впорядкування, відновлення та пакування вихідних файлів. Попередні зміни V2 у Reader, SQLite, індексації, UI та локалізації збережено.

**Жодні дії не виконувалися над реальною бібліотекою.** Шляхи на кшталт `D:\Flib\Flib.db` і `D:\Другие` недоступні, тому фізичний ремонт авторських папок, впорядкування книг та міграції бази на справжніх даних **не проводилися**. Тести використовували тимчасові каталоги.

## 5. Чому змінено захист event log

- Сама опція `APPEND` не гарантує неподільності **серії окремих write** між паралельними авторами.
- Обмежені 64 JVM-монітори не накопичують безкінечну мапу блокувань на кожен маніфест.
- `FileLock` покликаний серіалізувати незалежні процеси, які використовують цей самий протокол. На нестандартних файлових системах перевірка підтримки/поведінки потрібна окремо.
- Незавершений хвіст журналу **не видаляється і не виправляється автоматично**: новий запис зупиняється, щоб залишити докази для recovery. Це fail-closed і може вимагати ручного відновлення.

## 6. Залишкові ризики

**P0 (блокують production release):** (1) немає повного Maven/JavaFX/JUnit clean verify; (2) немає Windows-тестів блокувань/NTFS/ReFS/UNC, crash-persistence на справжньому диску; (3) немає приймання на **копії** каталогу; (4) текстова та аудіопозиції Reader з V2 досі ділять одну SQLite-модель `anchor_id`; (5) незалежні некооперативні процеси, які змінюють журнал поза `FileLock`, залишаються загрозою і потребують ОС-рівневого сценарію.

**P1:** (1) JFR/heap, JavaFX, Lucene на синтетичному чи реальному каталозі ~596 тис. книг не профільовано; (2) повний UI-огляд вікон усіх трьох локалей не проведено; (3) масові зміни старих авторських папок до Windows smoke-test **не дозволяти**.

```bash

python tools/validate-language-catalogs.py
python tools/check-all-ui-localization.py

```

Окремо: тест примусового завершення процесу між snapshot/.events/SQLite commit, паралельні двопроцесні append на NTFS, симульована відмова диска, порівняння SHA-256 усіх файлових артефактів до/після, organizer preview та repair 1–10 папок **лише на копії**.

**Висновок:** V3 усуває конкретний відтворений ризик втрати crash-manifest, кілька підтверджених інваріантних порушень журналу та помилку прав виконання збірки. Повний релізний допуск не підтверджено; реальна бібліотека залишилася недоторканою.
