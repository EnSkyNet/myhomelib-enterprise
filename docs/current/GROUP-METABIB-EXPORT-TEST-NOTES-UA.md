# V34 — тестування експорту групи у переносний metabib

## Де перевіряти
У робочій колекції відкрийте «Групи», виберіть власну групу та в її контекстному меню натисніть «Експортувати групу (metabib)». Оберіть окрему теку для тесту.

Після успішного завершення має з'явитися **нова** підтека `MHL-<UUID>`, що містить `catalog.jsonl` і ZIP-файли `books-0001.zip`, `books-0002.zip` тощо. Кожний ZIP вміщує не більше ніж 1000 книг. Відсутні онлайн-книги **не завантажуються** автоматично.

## Регресійний тест після PR #135
1. Група з двома доступними книгами: перевірте кількість записів у `catalog.jsonl` і фізичні файли у ZIP.
2. Група з однією доступною та однією локально недоступною книгою (немає файла або неможливо відкрити): експортується доступна книга, лічильник пропущених збільшується.
3. Група, де всі книги недоступні: програма повідомляє про неможливість експорту, **не створює** порожній `MHL-...` пакет.
4. Пошкоджений потік читання, помилка запису ZIP, перерваний потік або зміна активної колекції: експорт завершується помилкою, тимчасові `.mhl-metabib-...` дані очищуються.
5. Перемістіть успішний пакет в іншу тестову теку й імпортуйте `catalog.jsonl` у нову тестову колекцію; ZIP мають лежати поруч із каталогом. Перевірте авторів, назви, ISBN, місто, видавництво і розмір файлів.

## Обмеження
- Це експорт **однієї** поточної колекції, не кросколекційний експорт; див. issue #132.
- Жодні файли джерела не видаляються. Робота виконується потоково з лімітом 512 МіБ на окрему книгу.
- Відновлення після обриву експорту ще не передбачено; новий експорт створює новий пакет.
- Якщо виконується перевірка на реальних великих архівах, зберігайте окремо журнал застосунку для повторюваної діагностики.
