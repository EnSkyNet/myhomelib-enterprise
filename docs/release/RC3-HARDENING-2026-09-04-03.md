# MyHomeLib Enterprise 7.1.0 RC3 — hardening checkpoint 03, 2026-09-04

This checkpoint records the release-hardening work completed after the migration/crash/Reader pass.
It intentionally distinguishes checks executed in this Linux/offline environment from Windows-only acceptance.

## Online update commit and Retry safety

- The durable catalog-update `.pending` marker is now the explicit commit boundary.
- A successful update cannot be returned while that marker still exists. The marker is removed strictly after
  `recordApplied`; the now-non-authoritative checkpoint file is then cleaned up best-effort.
- UI numeric progress callbacks are isolated from the transaction/recovery state machine. A callback exception at
  100% can no longer turn a committed update into a rollback attempt.
- Added regression coverage proving that an import failure rolls back the SQLite checkpoint and that an immediate
  second Retry can complete and advance the applied catalog version.

## Backup / Restore / Export crash safety

- Restore no longer chooses an arbitrary `.db` when a backup directory contains more than one database.
  It selects the database matching the active collection DB filename; if no match exists and multiple candidates
  remain, Restore aborts before closing the live collection.
- Existing staged/validated Restore and `.restore.pending` recovery semantics remain covered.
- Added Export crash-safety tests proving that a failed converter cannot destroy an existing overwrite target or
  leave a partial staging file, while a successful conversion atomically replaces the target.

## Release packaging hardening

- Packaging and release scripts derive `7.1.0` from `pom.xml`; release artifact names no longer depend on a
  hard-coded version.
- Windows native packaging uses one stable `--win-upgrade-uuid`, Start Menu + desktop shortcuts, and the JDK 21
  `--win-per-user-install` option so the installer targets a normal user account.
- Corrected an invalid draft option (`--win-per-user`) before release: JDK 21 requires
  `--win-per-user-install`.
- Linux/macOS checksum generation now uses Python stdlib rather than GNU-only `sort -z`/`sha256sum`, producing
  deterministic relative slash-separated paths and atomic `SHA256SUMS` publication.
- Raw jpackage app-image directories are treated as intermediate build output. After smoke/installer creation they
  are removed before checksums and artifact upload; published checksums therefore reference only published files.
- CI builds/validates Linux, Windows and macOS artifacts separately, then a single tag-only publish job waits for
  all platforms and creates the GitHub Release exactly once with unified checksums.
- Static release validation now rejects a missing/invalid Windows per-user option, missing/invalid upgrade UUID,
  multiple GitHub release publishers, and GNU-only checksum regressions.
