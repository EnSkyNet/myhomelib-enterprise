# Резервне копіювання та перенесення даних користувача

MyHomeLib створює узгоджений знімок SQLite через `VACUUM INTO`, тому активну WAL-базу не копіюють як звичайний файл. Резервна копія може містити базу даних та переносний файл `user-data.json`; похідні індекси й кеші за потреби відновлюються окремо.

`user-data.json` — версійний переносний маніфест. Він містить оцінки, прогрес і відгуки, закладки, підсвічування та нотатки з текстовими прив’язками, історію і статистику читання, групи/обране, збережені пошуки, спільні фільтри, глобальні налаштування читалки та налаштування окремих книг. Книжкові записи зіставляються насамперед за стабільним `LibID`; внутрішній ідентифікатор книги використовується лише як запасний варіант для тієї самої колекції.

Під час відновлення доступні два режими:

- **Повне відновлення** — поетапна заміна SQLite з повторним відкриттям колекції та послідовним застосуванням міграцій Flyway; сумісне зі старими резервними копіями, де є лише `.db`.
- **Лише дані користувача** — каталогова база та метадані книг не замінюються; `user-data.json` накладається на поточний каталог за `LibID`. Це рекомендований режим після оновлення або повторного імпорту INPX.

Формат даних має версію схеми та послідовні міграції попередніх форматів. Перед руйнівним обслуговуванням колекції створюється окрема страхувальна резервна копія. Не замінюйте файли активної БД вручну під час роботи програми.
